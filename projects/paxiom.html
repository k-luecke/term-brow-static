Paxiom

x402 proves a payment; Paxiom proves what the payment bought — Ed25519 proof-of-delivery receipts, zero-dependency TypeScript & Python SDKs, MCP servers, and live Base Mainnet USDC settlement verification.

LIVE · v0.1.3NPM · PYPI · MCPMPT R&D SUBSTRATE

Shipped product (Receipts v0)

paxiom.receipt.v0 binds the HTTP request, canonicalized output hash (deterministic canonical JSON + SHA-256), and payment reference under an Ed25519 signature. Published at v0.1.3 on npm (@paxiom/receipts), PyPI (paxiom-receipts), and the Official MCP Registry (io.github.k-luecke/paxiom-receipts).

Live Base Mainnet verifier

https://api.paxiom.org serves free deterministic offline verification (POST /v1/receipt/verify), paid Base & Base-Sepolia USDC Transfer-log verification with Paxiom counter-attestation (POST /v1/receipt/verify-live, $0.002 USDC), and SSRF-hardened pre-payment x402 seller preflight scans (POST /v1/x402/preflight, $0.01 USDC).

Upstream substrate prototype

The companion k-luecke/paxiom repository (159 tests) verifies archived Ethereum account/storage proofs against block stateRoot values using Merkle-Patricia verification, accompanied by an explicit self-audit.

Explicit boundaries

Offline receipt verification reports unverified tx claims honestly as settlement_claimed_not_checked without touching RPC. Recursive zero-knowledge proofs over full Ethereum consensus history remain upstream R&D, not a shipped product claim.
